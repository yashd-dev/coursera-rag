# Speculative Sampling: Accelerating LLM Decoding

**Problem:** Transformer decoding is memory-bandwidth bound; generating 500B+ parameter models necessitates model parallelism with communication overheads. Each new token depends on the prior, requiring many sequential transformer calls for sequence sampling.

**Method:** Speculative sampling (SpS) introduces a draft model to generate short candidate drafts of length K. These drafts are scored by the target (larger) model using a modified rejection sampling scheme that preserves the target distribution within hardware numerics. When draft and target distributions agree strongly, multiple tokens are accepted per target model call.

**Reported Results:** 
- Benchmarked with Chinchilla (70B parameter model)
- Achieves 2–2.5× decoding speedup in distributed setup
- Mean tokens per second with SpS exceeds the idealized ceiling on auto-regressive sampling speed imposed by memory bandwidth
- No model modifications or distribution biasing required

**Limitations:** Segment ends mid-discussion of related work on sampling latency improvements; no explicit limitations stated within this segment.

**Direct Quotes:**
> "Our algorithm relies on the observation that the latency of parallel scoring of short continuations, generated by a faster but less powerful draft model, is comparable to that of sampling a single token from the larger target model."
> "We benchmark speculative sampling with Chinchilla, a 70 billion parameter language model, achieving a 2–2.5× decoding speedup in a distributed setup, without compromising the sample quality or making modifications to the model itself."

- **Problem**: Auto-regressive sampling (ArS) is memory bandwidth bound; each accelerator chip call generates only one token per batch, creating latency that scales with model size and inter-device communication overhead.

- **Method**: Combines model compression (pruning, quantisation to int8/int4, distillation), multi-query attention, and low-level TPU optimisations to improve serving latency and efficiency.

# chen2023accelerating (3/8)

**Problem**  
- Investigates accelerating LLM decoding via speculative sampling using draft models to generate candidate token continuations.

**Method**  
- Drafts $K$ tokens $\tilde{x}_1, \dots, \tilde{x}_K$ from proposal distribution $q$.  
- For $t=1:K$, samples $r \sim U[0,1]$; accepts $\tilde{x}_{n+t}$ if $r < \min(1, q(\tilde{x}_{n+t}|x_1,\dots,x_n)/p(\tilde{x}_{n+t}|x_1,\dots,x_n))$, else resamples $x_{n+t}$ from $(q(x|x_1,\dots) - p(x|x_1,\dots))_+$ and exits loop.  
- If all $K$ tokens accepted, samples extra token $x_{n+K+1} \sim q(x|x_1,\dots,x_n,\tilde{x}_1,\dots,\tilde{x}_K)$ and increments $n$.  
- Continues while loop iteratively.

**Reported results**  
- No explicit numeric results in this segment; methodology described for recovering target model distribution via modified rejection sampling of drafted tokens.

**Limitations**  
- Overhead sources may depend on transformer implementation, positioning encoding, decoding method (e.g., nucleus sampling sort), and hardware.  
- For small $K$, all-reduce and attention memory bandwidth show little delta between scoring and sampling, but conditions must dominate for scoring not to be significantly slower.

**Exact quotes**  
- “For speculative sampling (See algorithm 2), we first make the observation that computing the logits of a short continuation of $K$ tokens in parallel has a very similar latency to that of sampling a single token.” (p. 3)  
- “Given a sequence of tokens $x_1, \dots, x_n$, and $K$ draft tokens $\tilde{x}_{n+1}, \dots, \tilde{x}_{n+K}$ generated from $p(.,.)$, we accept $\tilde{x}_{n+1}$ with probability: $\min(1, q(\tilde{x}_{n+1}|x_1,\dots,x_n)/p(\tilde{x}_{n+1}|x_1,\dots,x_n))$.” (p. 3)

**problem**  
- Addresses decoding bottleneck in LLM inference; proposes speculative sampling to accelerate generation by drafting multiple tokens per loop.  

**method**  
- Draft-accept loop generates at least one token per iteration; if first token rejected, resampled to ensure validity.  
- Final draft token provides logits for next token; if all drafted tokens accepted, achieve maximum of K+1 tokens per loop (vs K for naive).  
- Probabilities modifiable via nucleus/top-k sampling and temperature before applying rejection sampling; acceptance rate robust to parameter choices.  
- Method compatible with quantisation, multi-query attention, and other optimisation techniques as it does not interact with transformer body.  
- Draft model chosen for high acceptance rate/low latency; options include multi-head in target model, sequence-level distillation, or using smaller target-model variant.  

**reported results**  
- 4B parameter draft model trained on 16 TPU v4s (same hardware as Chinchilla research setup).  
- Shares tokenizer and dataset with Chinchilla; 8 layers, slightly smaller width.  
- Sampling speed: 1.8ms/token (draft) vs 14.1ms/token (Chinchilla).  
- Table 1: With K=4, speculative sampling yields speed-ups of 1.92× (XSum ROUGE-2) and 2.47× (HumanEval 100 Shot) over naive decoding.  
- Acceptance rates and ROUGE-2 scores reported: ArS/Nucleus XSum 0.112 ROUGE-2 at 7.52ms/token; ArS/Nucleus HumanEval 47.0% at 5.73ms/token.  

**limitations**  
- Impractical to naively choose small model as draft for distributed setups; different models require optimal inference setups.  
- Sequence-level distillation requires large compute budget, limiting scalability.  
- Engineering convenience dependent on existing robust tooling for target-model training.  

**two short exact quotes**  
- “At least one token will always be generated from a draft-accept loop – if the first token is rejected, a valid token is resampled.” (P5)  
- “We have observed that the overall acceptance rate is robust to the exact parameters used.” (P5)

# chen2023accelerating.6.txt Analysis (Pages 7–8)

## Problem & Method
- **Problem**: Decoding efficiency of large language models; trade-off between draft length and scoring overhead.
- **Method**: Speculative sampling with modified rejection scheme; draft model samples K tokens, large model scores them; acceptance ratio measured as tokens accepted divided by (K + 1).
- **Key finding**: Average tokens accepted / (K + 1) measures overall efficiency; decreases as K increases due to dependency on prior token acceptance.

## Reported Results
- **Performance**: Average time per loop increases approximately linearly with K due to more model calls.
- **Speedup trade-off**: Increasing K reduces scoring calls from large model but increases total loop time linearly; overall speedup plateaus or degrades with larger K.
- **Specific example**: XSum with nucleus latency minimized at K = 3.
- **Variance**: Larger K increases variance of time to generate full sequence; problematic for P90/P99 latency-sensitive settings.
- **Empirical validation**: Technique lossless downstream; verified with Chinchilla 70B using easy-to-train draft model.

## Limitations
- Efficiency decreases with larger K due to token dependency on prior acceptance.
- Speedup plateaus or degrades beyond optimal K (e.g., K = 3 for XSum).
- Increased variance in generation time harms P90/P99 latency scenarios.

## Exact Quotes
- "The average number of tokens accepted divided by K + 1 – this serves as a measure of the overall efficiency of the modified rejection scheme, which decreases with the lookahead." (p. 7)
- "As K increases, we need fewer scoring calls from the large models to generate the same sequence length, potentially giving us a larger speedup. However, the total loop time increases approximately linearly with the larger number of draft model calls and small increases in the scoring time." (p. 7)

# Speculative Sampling Acceleration

**Problem:**  
Improving LLM decoding efficiency through speculative sampling, where a smaller "draft" model generates candidate tokens for a larger "target" model to accept or reject (chen2023accelerating.8.txt, 10).

**Method:**  
Modified rejection sampling framework where draft model $q$ proposes samples; target model $p$ uses acceptance probability $\min(1, p(x)/q(x))$. Resampling occurs on rejection to recover the target distribution exactly (10-11).
