# Leviathan 2022: Fast Inference via Speculative Decoding

## Problem
- Inference from large autoregressive models is slow due to serial decoding: generating K tokens requires K serial model runs (p.1)
- Standard approaches reduce inference cost equally for all inputs or require model re-training/architecture changes (p.1)
- Not all inference steps are equal; some require large models while others can be approximated (p.1)

## Method
- Introduces **speculative decoding**: samples from autoregressive models faster without output changes by computing multiple tokens in parallel (p.1)
- Core observations: (1) hard LM tasks include easier subtasks approximable by efficient models; (2) speculative execution with novel sampling enables exact decoding from large models in parallel (p.1)
- Accelerates off-the-shelf models without retraining or architecture changes (p.1)
- Demonstrated on T5-XXL with 2X-3X acceleration vs. standard T5X, identical outputs (p.1)
- Inference not bottlenecked on arithmetic but memory bandwidth/communication; increasing concurrency is complementary approach (p.1-2)

## Reported Results
- 2X-3X acceleration on T5-XXL versus standard T5X implementation (p.1)
- Identical outputs maintained (p.1)

## Limitations
- Speculative execution requires efficient mechanism to suggest likely-needed tasks (p.2)
- Generalizes speculative execution to stochastic setting where task might be needed with some probability (p.2)

## Exact Quotes
> "decoding K tokens takes K serial runs of the model" (p.1)
> 
> "we can make exact decoding from the large models faster, by running them in parallel on the outputs of the approximation models" (p.1)

**problem**  
- Accelerate inference of large autoregressive Transformers without altering output distributions.  
- Address computational bottleneck of serial decoding in models like GPT and T5.  

**method**  
- Propose speculative decoding: use an efficient approximation model $M_q$ to generate $\gamma$ candidate tokens, then evaluate all guesses in parallel using the target model $M_p$.  
- Accept guesses that maintain identical output distribution to $M_p$; sample a correction token if the first rejection occurs, or add an extra token if all are accepted.  
- Ensure at least one new token per parallel run, never increasing serial runs beyond standard autoregressive decoding.  

**reported results**  
- Page 2: Method analyzed on 97M parameter GPT (lm1b), 11B parameter T5-XXL, and 137B parameter LaMDA.  
- T5-XXL implementation shows 2X–3X out-of-the-box latency improvement versus robust T5X (Roberts et al., 2022), with no output changes.  
- Example: 38-token sentence generated with 9 serial runs of 97M target model via 6M approximation model, preserving generation probability.  

**limitations**  
- Performance gains dependent on approximation model quality relative to target model.  
- Assumes compute resources available; memory bandwidth bottleneck is key scenario.  

**exact quotes**  
- “For example, the sentence in Figure 1, consisting of 38 tokens, was generated by our method with only 9 serial runs of a larger target model (97M parameters) thanks to a smaller and more efficient approximation model (6M parameters), while the probability of generating it is unchanged.” (p. 2)  
- “Our method is easy to employ in actual production settings, doesn’t require training new models, and doesn’t change the outputs. Therefore, in common situations where memory bandwidth is the bottleneck, and compute resources are available, it may be a good default to accelerate sampling from autoregressive models like Transformers.” (p. 2)

**problem**  
- Paper addresses accelerating autoregressive decoding from transformer models. (P2 cont.)

**method**  
- Introduces speculative sampling and speculative decoding as a generalization of speculative execution to the stochastic setting. (P2 cont.)  
- Speculative sampling accepts a token from proposal distribution q if q(x) ≤ p(x); otherwise rejects with probability 1−p(x)/q(x) and samples from an adjusted distribution p₀. (P3)  
- Speculative decoding runs Mp and Mq in parallel on guessed tokens, accepts n tokens where rᵢ > pqᵢ(x), and returns one token from Mp plus n tokens from Mq. (P3)  
- α = E[β] quantifies how well Mq approximates Mp; under i.i.d. assumption, tokens per run follow a capped geometric distribution with success probability 1−α and cap γ+1. (P3)

**reported results**  
- Expected tokens per iteration follow equation E(tokens) = (1−αγ+1)/(1−α). (P3)  
- Figure 2 plots expected tokens vs. α for γ ∈ {1,3,5,7}. (P3)  
- DLK(p,q) = 1 − Σₓ min(p(x),q(x))/Σₓ (p(x)+q(x))/2 provides a divergence measure; Lemma 3.3 links it to acceptance rate. (P3)

**limitations**  
- Assumes i.i.d. βs to derive capped geometric token count; real data may violate this. (P3)  
- Does not modify model architectures, training regimes, or output distributions. (P2 cont.)

**two short exact quotes**

# Leviathan 2022: Fast Inference via Speculative Decoding (Segment 4)

## Problem
- Addresses inference latency of Transformers via speculative decoding
- Reduces serial calls to target model $M_p$ by analyzing token generation reduction

## Method
- Proposes algorithm generating tokens via approximation model $M_q$ then verifying against $M_p$
- Accept/reject decisions based on DLK (Pearson) divergence $D_{KL}(p, q)$
- Corollary 3.6: $\alpha = 1 - \mathbb{E}[D_{KL}(p, q)] = \mathbb{E}[\min(p, q)]$, measures model similarity
- Table 3 provides empirically observed $\alpha$ values
- Theorem 3.8: Expected walltime improvement factor = $\frac{(1-\alpha)(\gamma c + 1)}{1 - \alpha\gamma + 1}$
- Theorem 3.11: Expected factor of increase in total operations = $\frac{(1-\alpha)(\gamma\hat{c} + \gamma + 1)}{1 - \alpha\gamma + 1}$
- Definition 3.7: $c$ = cost coefficient = ratio of single run times $M_q / M_p$; in experiments $c < 0.05$ often negligibly close to 0
- Definition 3.10: $\hat{c}$ = ratio of arithmetic operations per token $M_q / M_p$

## Reported Results
- Algorithm 1 performs $\gamma + 1$ runs of $M_p$ in parallel
- Corollary 3.4: DLK$(p, q)$ is symmetric divergence in $[0, 1]$
- Corollary 3.9: If $\alpha > c$, exists $\gamma$ where DLK$(p, q) = 0 \iff p = q$; improvement factor at least $\frac{1+\alpha}{1+c}$
- Corollary 3.9: DLK$(p, q) = 1 \iff$ $p$ and $q$ have disjoint support
- Improvement factor depends on $\alpha$, $\gamma$, and $c$; when $\alpha$ low, increase in arithmetic operations is high, and vice-versa
- For Transformers, total arithmetic operations by Algorithm 1 (not counting $M_q$ runs) bounded above by single run of same-size Transformer encoder

## Limitations
- i.i.d. assumption required for algorithm reduction claims
- Requires sufficient compute resources to support increased concurrency (Section 3.4)
- Walltime analysis assumes $\gamma + 1$ concurrent evaluations of $M_p$ without increasing walltime
- Rejecting guesses wastes computation; total operations may exceed standard decoding algorithm

## Exact Quotes
- "If we get an improvement for $\gamma$, we'd also get an improvement for any $0 < \gamma^* < \gamma$, so for our method to yield an improvement, we can evaluate Theorem 3.8 for $\gamma = 1$, yielding $(1-\alpha)(c+1) / 1+c$" (Page 4 continued)
- "Let $\hat{c}$ be the ratio of arithmetic operations per token of the approximation model $M_q$ to that of the target model $M_p$." (Page 4 continued)

**Problem**
Speculative decoding accelerates transformer inference by using a smaller "approximation model" Mq to draft tokens verified by the target model Mp. The method aims to reduce walltime while maintaining output quality.

**Method**
The algorithm interleaves calls to Mq and Mp. A parameter γ controls how many Mq calls precede each Mp call. The parameter α represents the fraction of Mp calls avoided. Simple, parameter-less approximation models (e.g., copying context prefixes, non-autoregressive models, random token selection) can be deployed with negligible production overhead.

**Reported Results**
*   **Translation (EnDe):** Speedups of 1.4X to 3.4X. With γ=7 and T5-Small Mq, α=0.82 and 3.4X speedup (temp=0); α=0.75 and 3.1X speedup (temp=1).

*   **Temperature effect:** α and walltime improvement are higher for argmax sampling (temp=0) than standard sampling (temp=1).

**Limitations**
*   The theoretical bound does not hold if Mp verifications are skipped.
*   Reported speedups are modest for summarization compared to translation.
*   Speedups decrease as the approximation model size (Mq) increases.

# Leviathan 2022 (8/12) – Compact Notes

- **Problem:** Autoregressive transformer decoding is bottlenecked by low memory-to-arithmetic-operation ratios; prior acceleration methods either restrict to greedy decoding, require custom training, or sacrifice output fidelity.

- **Method:** Speculative sampling enables efficient *stochastic* speculative execution by running an approximation model in parallel with the target model, accepting/rejecting outputs to guarantee identical distributions.

- **Reported results (Page 7 continued):** T5 models (Small/Base/Large) and LaMDA (137B/2B/8B/100M) evaluated across n-gram and T5 baselines with temperature settings T=0 and T=1. Metrics (0.07–0.82) reflect approximation quality under varied compute/token configurations.

- **Limitations (Page 8):** Latency improvements rely on increased concurrency and arithmetic operations; not viable when additional compute resources are unavailable. Text-only experimentation; cross-domain extension underexplored.

- **Exact quotes:**
  - “After we initially published our work, an independent implementation of speculative decoding (Chen et al., 2023) showed similar 2X–2.5X improvements on Chinchilla 70B.” (Page 8)
  - “We presented speculative sampling which enables efficient stochastic speculative execution — i.e. speculative execution in the stochastic setting.” (Page 8)

- **Acknowledgments note:** One limitation of speculative execution in general, and of speculative decoding in particular, is that latency is improved through increased concurrency at the cost of an increased number of arithmetic operations. Thus, the method is not helpful for configurations where additional computation resources are not available. However, in common cases where additional computation resources are available (...).

**Problem:** Accelerating inference speed for large language models (specifically LaMDA) without modifying model architecture or requiring retraining, while preserving output distribution.

**Method:** Speculative decoding using an approximation model (M_q) to generate multiple candidate tokens (γ guesses) per step. A verification model checks acceptance; rejected tokens fall back to the base model. Speedup occurs when the approximation model is faster.

**Reported results:** The method provides speedups when memory bandwidth is the bottleneck. Key benefits include no architecture changes, no retraining required, and guaranteed output distribution consistency. Implementation is straightforward for out-of-the-box models.

**Limitations:** Fixed approximation model and number of guesses (γ) throughout inference; varying them dynamically could yield improvements. Greater speedups possible with custom approximation models. Compatibility with beam search requires further investigation.

**Exact quotes:**
- "Our method provides the speedup with significant benefits: the model architecture doesn’t change, retraining isn’t required, and most importantly, the output distribution is guaranteed to stay the same."
- "Our method is easy to implement, and can be used to speedup inference using out-of-the-box models without developing and evaluating custom schemes."

**Problem**  
Explore speculative decoding with a small "draft" model (Mq) to accelerate inference of a large target model (Mp), specifically evaluating beam search and lenience mechanisms to balance speed and output distribution integrity. (Page 12 continued)

**Method**  
Propose a speculative decoding pipeline: generate candidates with Mq under beam width u ≥ w for γ steps, verify candidates in parallel with Mp (compute budget: (w + uγ) runs of Mp), and accept guesses of Mq only if top_w(Mp) ⊆ top_u(Mq) to match regular beam search results. Investigate a lenience parameter l ∈ [0,1] that scales q(x) before comparing with p(x), guaranteeing no token exceeds p(x)^l probability. (Page 12 continued)

**Reported results**  
- Table 5 α-values for Mp=T5-XXL, Mq=T5-small on EN-DE: l=1→0.07/0.19/0.62/0.68 (unigram/bigram); l=0.5→0.1/0.23/0.71/0.8; l=0.3→0.11/0.25/0.76/0.83; l=0.1→0.16/0.32/0.84/0.90.

**Limitations**  
- Lenience with temperature=0 precluded; alternative lenience method yields α values but does not guarantee diversity.
