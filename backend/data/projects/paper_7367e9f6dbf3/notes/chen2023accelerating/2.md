# chen2023accelerating (PAGE 2 continued)

- **Problem**: Auto-regressive sampling (ArS) is memory bandwidth bound; each accelerator chip call generates only one token per batch, creating latency that scales with model size and inter-device communication overhead.

- **Method**: Combines model compression (pruning, quantisation to int8/int4, distillation), multi-query attention, and low-level TPU optimisations to improve serving latency and efficiency.

- **Reported results**: Pope et al. (2022) greatly improved serving latency and efficiency for PaLM 540B using combined techniques, though results focus on throughput at larger batch sizes rather than latency.

- **Limitations**: Techniques optimised for throughput at large batch sizes; not adapted to typical language model use-cases; none scaled to distributed setups necessary for decoders with tens/hundreds of billions of parameters.

- **Quote 1**: "During sampling, a cache of the keys and values is maintained for every attention layer, and could become a memory bandwidth bottleneck as the batch size increases." (PAGE 2 continued)

- **Quote 2**: "The observation that model size contributes less to the final performance than expected (Hoffmann et al., 2022) has also encouraged smaller language models in general." (PAGE 2 continued)
