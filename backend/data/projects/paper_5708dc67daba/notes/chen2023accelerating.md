# Speculative Sampling (Chen et al., 2023)

## Problem
- Transformer decoding remains highly costly and inefficient despite 500B+ parameter scaling
- Sampling is memory bandwidth bound; generation time proportional to parameter and memory size
- Autoregressive models require many transformer calls per sequence due to token dependency
- Goal: accelerate sampling for latency-critical applications without modifying target model

## Method
- **Speculative sampling (SpS) algorithm** in three steps:
  1. Generate short draft of length K using faster draft model (parallel or autoregressive)
  2. Score draft using larger target model
  3. Accept subset of draft tokens left-to-right via modified rejection sampling preserving target distribution
- Intuition: "obvious" sequences show strong agreement between draft and target distributions
- Enables multiple tokens per target model call when distributions align

## Reported Results
- **2–2.5× decoding speedup** when sampling from Chinchilla (70B parameters) in distributed setup
- No compromise to sample quality; no model modifications required
- Mean tokens per second with SpS often exceeds idealized ceiling on autoregressive sampling speed imposed by memory bandwidth
- Benchmarked with Chinchilla; draft model details and exact acceptance rates not specified in this segment

## Limitations
- Segment ends mid-sentence in Related Work section ("Since sampling performance is heavily coupled with the mod")
- No domain-specific evaluation beyond Chinchilla benchmark reported
- Draft model architecture and training details not provided
- Speedup ratio varies by evaluation domain

# chen2023accelerating (Page 2 continued)

- **Problem**: Auto-regressive sampling (ArS) is memory-bandwidth bound; each accelerator chip generates only one token per batch, creating a hard ceiling on sampling speed limited by model size divided by total memory bandwidth. Larger models require multi-accelerator serving, adding inter-device communication overhead.

- **Method**: Combines model compression techniques (pruning, quantization to int8/int4, distillation) with low-level TPU optimisations. Speculative sampling (SpS) uses a draft model to generate multiple candidate tokens in parallel, which the target model verifies. Multi-query attention shrinks the key-value cache but maximises throughput at larger batch sizes rather than latency.

- **Reported results**: Pope et al. (2022) greatly improved serving latency and efficiency of PaLM 540B using combined techniques. Speculative decoding (Leviathan et al., 2022), pursued concurrently and independently, shares the core underlying idea but focuses on distributed serving for large models with incremental optimisations.

- **Limitations**: Existing efficiency methods (block parallel sampling, aggressive decoding, parallel image-domain models) either work only with greedy sampling, bias results, or focus on other modalities. None have been scaled to distributed setups necessary for tens/hundreds of billions of parameters.

# Chen 2023: Accelerating LLM Decoding (Segment 3/8)

## Problem & Method
- Targets speculative sampling acceleration via conditional scoring and modified rejection sampling (algorithmic framework)
- Proposes rejection sampling to recover target model distribution from draft model samples
- Acceptance probability for draft token $x_{\tilde{n}+1}$: $\min\left(1, \frac{q(x_{\tilde{n}+1}|x_1,...,x_n)}{p(x_{\tilde{n}+1}|x_1,...,x_n)}\right)$

# Chen 2023: Accelerating LLM Decoding with Speculative Sampling (Page 4–6)

## Problem
- Speculative sampling aims to accelerate LLM decoding by generating multiple candidate tokens per iteration.
- Hardware numerics and inference constraints impose practical limits on speed improvements.

## Method
- **Core mechanism**: A draft model proposes K tokens; a target model evaluates acceptance via rejection sampling.
- **Guarantee**: At least one token is always generated per loop; if the first is rejected, a valid token is resampled.
- **Yield**: When all K drafted tokens are accepted, the loop produces K+1 tokens total (vs. K in naive implementation).
- **Compatibility**: Does not interact with the transformer body, enabling combination with quantisation, multi-query attention, etc.
- **Draft model choice**: Can be a smaller version of the target model, trained via sequence-level distillation, or integrated via multiple heads. Practicality constraints include data/compute costs and engineering overhead.

## Reported Results
- **Hardware**: 4B parameter draft model trained on 16 TPU v4s (same setup as serving Chinchilla for research).
- **Speed**: Draft model achieves 1.8 ms/token vs. 14.1 ms/token for Chinchilla (7× faster sampling).
- **Performance (Page 6, Table 1)**:
  - XSum (nucleus p=0.8): ArS speedup 1.92×; SpS speedup 2.01× (Greedy).
  - HumanEval (p=0.95, temp=0.8): Acceptance rate improves from 45.1% to 47.0%; token time drops from 14.1 ms to 5.73 ms (≈2.46× speedup).

## Limitations
- Distributed setups require careful orchestration; naive small-model selection is insufficient due to varying optimal inference configurations across model scales.
- Sequence-level distillation (Ge et al., 2022) demands large compute budgets, limiting practicality for large-scale applications.
- Acceptance rates and speedups are benchmark-dependent (XSum vs. HumanEval exhibit different dynamics).
